# Два запуска готовых аппаратных комплектов

Архивы не пересобирать и не изменять. Использовать прежний работающий title
override / application mode, без изменений Atmosphère и частот. Сначала
скопировать старые logs/config/save на ПК. Исходные слоты не перезаписывать.

## 1. Основная игра E2E-5.16

`build/e2e516/hardware-e2e516-03651ce.zip` → существующая папка
`sdmc:/switch/space-rangers-hd-a-war-apart/`; перенести только готовую NRO,
ELF оставить на ПК. Рядом с NRO: `perf-mode.txt=basic`, `scene-mode.txt=on`.

1. Новая игра → генерация → персонаж → станция/ангар → карта → меню → назад.
   Фото первого чужого фона и название перехода. На карте один приказ движения
   и один ход; отметить визуальный отклик и звуки при задержке.
2. Один обычный аркадный бой: движение, стрельба, столкновения, взрыв и результат.
   Короткое видео; привычный CPU/GPU overlay допустим без изменения частот.
3. После перелёта сохранить тестовую копию новым именем `Тест516`.
   Записать результат сообщения. Перезапуск ради загрузки не требуется:
   проверка загрузки после нового процесса остаётся HARDWARE_PENDING.

Передать всю `sdmc:/switch/space-rangers-hd-a-war-apart/logs/`, включая
`perf515.csv`, `perf515-stage.log`, `scene-*.ppm` и прочие созданные журналы.
Ожидается `build_git=03651ce` в stage log. Имена perf515 правильные.
Снимков не более 48; это CPU-снимки, не GPU readback. Разовые затраты capture/IO
учитывать отдельно при анализе аркады. Если снимки исчерпаны до дефекта, фото
и журналы всё равно сохранить; дополнительный запуск не требуется.

## 2. Отдельный MatrixGame GPU smoke

`build/e2e515/hardware-gpu-a224fa4.zip` → его отдельная папка
`sdmc:/switch/matrixgame-deko-smoke/` вместе с готовым model.vo.
Запустить `MatrixGame real VO GPU smoke`, дождаться PASS/FAIL, снять экран,
выйти B. Передать `sdmc:/switch/matrixgame-deko-smoke/gpu-smoke.log`.
Успех — `END status=PASS`, одного BEGIN недостаточно. Это проверка исходного
VO → GPU upload/draw/readback/recreate, а не нового bootstrap или боя.

К двум журналам приложить фото/видео, handheld/docked, порядок действий и
способ выхода. При аварии — соответствующий crash report. Ресурсы и исходные
сейвы в архив не включать. Оба результата до получения логов HARDWARE_PENDING.

Проверенные SHA-256 ZIP:

- Основной: `e1a1dec5f410b983d629ae538ad9b4ba063f89a8101af43d27ea00c6ce6a08a4`.
- GPU: `1c5cfebb2696bbf6db98bd2cd598956f468ef1ca8183bbf31271148c30103429`.

После получения: проверить идентичность сборок, связать кадры и переходы с
монотонными метками stage/CSV, отделить симуляцию/рендер/present/IO, сопоставить
с прошлым прогоном, проследить конкретную фазу отказа сейва и draw/readback GPU.
Причины считать подтверждёнными только по evidence; для каждого следующего
изменения указать адресную host-регрессию и оставшийся аппаратный критерий.
