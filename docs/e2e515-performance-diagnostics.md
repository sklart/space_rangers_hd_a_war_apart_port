# E2E-5.15: аппаратная диагностика основной игры

Отдельная Release Save ON / Audio ON сборка, без MatrixGame. Базовый аппаратный
комплект `hardware-main-7d3b4f5.zip` сохранён неизменным. Новый режим наблюдает
игру: логика, RNG, физика и планировщик не заменяются. Код не задаёт частоты,
не использует IPC sys-clk и не добавляет привилегированных сервисов.
До получения аппаратных файлов статус **HARDWARE PENDING**.

## Установка и режимы

Установить диагностическую NRO из отдельного комплекта в существующий каталог
`sdmc:/switch/space-rangers-hd-a-war-apart/`. Игровые ресурсы и config/Save не
перемещать. Matching ELF хранить на ПК. Сначала скопировать прежние логи,
config и сохранения на ПК; проверять запись на копиях данных.

Файл `sdmc:/switch/space-rangers-hd-a-war-apart/perf-mode.txt` читается **при запуске**:

| Первая строка | Режим |
|---|---|
| `basic` или файл отсутствует | Кадры, полный TimerTakt/DrawFrame, суммарный участок Advance, backlog, память, heartbeat |
| `detail` | Дополнительно каждый Advance, AI, физика, поиск столкновений, repel, вызовы огня/тяги/урона/ввода |
| `off` | Отключены performance samples; асинхронный журнал стадий запуска/ошибок остаётся |

Сменить файл и перезапустить приложение. Режим detail дороже basic: каждый
вложенный scope читает время и, если доступно, собственное CPU time потока.
Это не «бесплатная» трассировка. В basic подробные scopes не читают часы.
Для сравнения с прежней NRO использовать также сохранённый исходный комплект.

Запускать через hbmenu в application mode с полной памятью (title override).
Режим applet отдельно записать; не смешивать результаты этих режимов.
Оверлеи Status Monitor/Tesla во время базового прогона закрыть.

## Прогоны

1. **A, basic:** штатные настройки частот, без визуальных оверлеев. Одна
   исходная копия сейва, 60–90 секунд обычного аркадного боя: движение, огонь,
   столкновения, взрывы. Затем пауза/возврат и завершение боя. Сохранить видео
   с понятным моментом нажатия и реакцией игры. Сразу скопировать пару логов
   на ПК в каталог run-A.
2. **B, basic + внешняя телеметрия:** та же NRO/сцена/копия сейва, параметры
   графики/звука, режим питания и контроллер. Включить CSV установленного
   clock-модуля только если подтверждена поддержка. Частоты не менять.
   Скопировать игровые и внешние файлы одного прогона в run-B.
3. **C, detail, при необходимости:** повторить обычный бой и проблемный взрыв.
   Подробные вложенные этапы нужны для локализации; FPS этого режима нельзя
   напрямую выдавать за производительность basic. Скопировать в run-C.

Не сводить дефект к взрыву: долгие задержки были крайним проявлением общей
медленной работы аркады. До выбора причины сопоставить обычный бой и событие.
Mute/громкость 0 не отключают декодер: такой прогон не является Audio OFF.
Затраты источника/декодирования видны в асинхронном `perf audio cumulative`.

## Файлы на SD и ограничения

- `logs/perf515.csv`: события и измерения; максимум 16 МиБ.
- `logs/perf515-stage.log`: сообщения E2E и SessionLog, heartbeat/режим/ошибки;
  максимум 8 МиБ. В этой NRO диагностические сообщения идут сюда вместо
  синхронной записи e2e.log/SessionLog из игрового потока.
- На новом запуске предыдущая пара переименовывается в `*.1`; хранится только
  текущая и одна предыдущая пара, суммарно не более примерно 48 МиБ.
- После достижения лимита запись соответствующего файла останавливается с
  маркером `file_cap_reached`; поздние samples недоступны. Скопировать результаты
  после каждого прогона, не делать десятки запусков перед копированием.

Производители записывают только фиксированные строки в ограниченную очередь
(8192 записи, около 5 МиБ). При занятости/переполнении очередь теряет запись,
а не ждёт SD; потери считаются в `dropped`, усечения — в `truncated`.
Выделенный writer пишет пакетами и сбрасывает раз в секунду. В файлах есть
`perf_failed`, `log_failed`, `capped`. Отказ writer не должен считаться
свидетельством отсутствия тормозов. Хвост очереди после принудительного
закрытия/краша может потеряться; штатный выход дожидается завершения writer.
При аварийном исключении перед `_Exit` также вызывается Shutdown.

Снимки scene-*.ppm и E2E3 trace выключены в этой сборке, чтобы запись кадров
на SD не попадала в измеряемый рендер. Для отдельной проверки фонов остаётся
первоначальный аппаратный комплект с этими снимками.
Чтение игровых ресурсов и обычная запись сейва не маскируются профилировщиком.

## Смысл измерений

`mono_us` и все wall durations используют e2e_clock/armGetSystemTick.
Каждая секунда имеет `anchor` с CLOCK_REALTIME epoch_ms и длительностью
скобки чтения. Квантование epoch даёт ещё до миллисекунды неопределённости.
Это позволяет сопоставить uptime с внешним CSV, не используя календарные
часы для длительности тика. Сдвиг календарных часов свыше 100 мс отключает
автоматическую корреляцию анализатора.

| Запись | Значение |
|---|---|
| `frame` | Успешно завершённый SDL Present; wall_us — интервал, a — число реальных ArcadeTickCount increments с прошлого Present, b — max gap за процесс |
| `timer`, `draw` | Полные TimerTakt / DrawFrame; wall_us и cpu_us |
| `advance_total` | Исходный участок Obj->Advance вместе с проверкой DeletionPending/удалением; wall time |
| `advance`, `ai`, `physics`, `collision`, `repel` | Вложенные scopes подробного режима; не взаимоисключающие части |
| `fire_primary_call`, `fire_secondary_call`, `movement_call`, `damage_call`, `input_key_call` | Вызов настоящего handler, не гарантия успешного выстрела или нанесённого урона |
| `explosion_start` | Вход в существующую ветку Health <= 0; a=1 для PlayerArcadeShip, b=Health |
| `explosion_setup`, `explosion_complete` | Подготовка эффекта и callback окончания; специальных событий RNG не добавляется |
| `battle_open`, `battle_close`, `battle_exit`, `victory`, `pause_toggle` | Реальные границы экрана/результата/паузы |
| `prepare`, `upload`, `copy`, `present`, `presentation_total` | Этапы CPU/SDL wall time; не GPU timestamp queries |
| `backlog` | a — pending ms, b — доставленные миллисекундные callbacks последнего batch; это не число 20-мс тиков |
| `heartbeat` | wall_us — время с последнего завершённого Present, a — max gap, b — суммарное число логических тиков |
| `memory` | a/b — used/total bytes собственного процесса; -1 при отказе API |
| `writer_io` | Время fflush выделенного writer; не включает всё время fwrite/rotation |

CPU time — собственный thread tick count через публичный svcGetInfo; при
недоступности возвращается -1, без привилегированного fallback. GPU utilization
и GPU time этим не измеряются. Возврат из SDL Present не является датчиком
физической развёртки экрана. Таймеры включают стоимость инструментирования;
wall time включает ожидания. Вложенные scopes нельзя суммировать с родителями.

Независимый writer каждую секунду фиксирует `active`, `active_age_us`,
`last_completed` и время без кадра. При полной остановке writer/OS или очень
долгом SD I/O heartbeat тоже может отсутствовать: это пробел измерения.
Обычная 5-секундная статистика и counters звука остаются в stage log;
её p50/p95/p99 относятся к ограниченным 128 samples, не ко всей трассе.

## sys-clk / hoc-clk

На присланном фото включена строка **hoc-clk**. Версия самого модуля не видна;
`1.5.3` относится к показанному экрану Sysmodules. Точный fork/API и формат
установленного hoc-clk не подтверждены. `System RAM free` не является объёмом
памяти, доступной игре. Локального доступа к SD/его telemetry файлам пока нет.

Для оригинального sys-clk официально описаны `/config/sys-clk/context.csv`,
`log.txt`, `log.flag` и параметры секции `[values]`:
[README](https://github.com/retronx-team/sys-clk/blob/develop/README.md).
В исходнике CSV отдельно указаны requested `*_hz` и `*_real_hz`, температура
в milliC и power в mW:
[формат CSV](https://github.com/retronx-team/sys-clk/blob/develop/sysmodule/src/file_utils.cpp).

**Только при подтверждённой поддержке установленной версией** вручную добавить
в существующую `[values]`, предварительно сохранив config.ini:

```ini
temp_log_interval_ms=1000
freq_log_interval_ms=1000
csv_write_interval_ms=1000
```

Не создавать вторую секцию, не перезаписывать файл и не менять poll_interval_ms,
профили частот/overrides. Для соответствующей версии log.flag включает log.txt;
сохранить прежнее состояние flag и после прогона вернуть его. Не переносить эти
настройки автоматически на hoc-clk по одному названию. Если CSV недоступен,
продолжить прогон A средствами игры и отметить EXTERNAL TELEMETRY UNAVAILABLE.
Файлы clock-модуля имеют собственную ротацию/лимиты, которыми NRO не управляет.

Скопировать также существующие context.csv/log.txt из фактического каталога
модуля, сведения о его версии и режиме питания. CSV Title ID должен относиться
к тому же приложению; applet и title override могут давать разные ID.

## Анализ на ПК

Скрипт читает входы, записывает результат только в новый каталог:

```powershell
py -3 tools/e2e515_perf_analyze.py --game run-B/perf515.csv --stage-log run-B/perf515-stage.log --sys-clk-csv run-B/context.csv --sys-clk-log run-B/log.txt --out build/e2e515/run-B-analysis
```

Параметры sys-clk необязательны. Для графиков нужен matplotlib в используемом
интерпретаторе (`python -m pip install matplotlib` в выбранной отдельной среде).
Без него CSV/JSON/табличный report.md всё равно создаются, а plot_status явно
сообщает об отсутствии графика. В текущей рабочей среде зависимости установлены
только в ignored `build/e2e515/analysis-libs`, без изменения системного Python.

Title ID определяется из stage log; `--title-id 0100...` задаёт его явно.
Корреляция идёт только с этим приложением, ближайший sample должен попадать в
`--max-align-ms` (по умолчанию 1500 мс). Числовой timestamp распознаётся как
epoch s/ms/us/ns; текстовое время без timezone требует явного
`--csv-utc-offset-minutes`, иначе не угадывается. Неизвестные столбцы сохраняются
в raw; неизвестные единицы/версия не превращаются в вымышленные метрики.
Заданные частоты никогда не подставляются вместо отсутствующих фактических.

Результаты: summary.json (качество/статистика), aligned.csv (игровые кадры и
допустимые совпадения), sysclk-normalized.json (включая raw), report.md и
performance.png при наличии matplotlib. Последний график использует общий
начальный момент игры; панели частот относятся к matching Title ID.

После получения настоящих файлов отдельно установить, что подтверждают данные:
CPU, GPU, backlog, лишняя отрисовка, память либо частоты/температура. Анализатор
не назначает причину по максимальному scope или одной частоте: до проверки
сравнения причина остаётся UNDETERMINED. На этом этапе готовность инструмента
не означает завершение аппаратной диагностики.

## Воспроизведение сборки

Отдельный каталог `port/switch/build/e2e-game-perf515`, профиль Release/Save ON.
При первой генерации может потребоваться обновление локальной effective manifest
(старые checked manifests стандартной сборки не заменять):

```powershell
py -3 tools/e2e_arm64_build.py --profile release --experimental-e2e4-combined --enable-experimental-saves --no-e2e3-trace --performance-diagnostics --preflight-only
py -3 tools/audit_win32_surface.py --effective --build-root port/switch/build/e2e-game-perf515 --manifest port/switch/build/e2e-game-perf515/effective-import-manifest.json
py -3 tools/e2e_arm64_build.py --profile release --experimental-e2e4-combined --enable-experimental-saves --no-e2e3-trace --performance-diagnostics
```

Для совершенно пустого build сначала скопировать checked Save ON manifest в
локальный effective-import-manifest.json как seed, затем выполнить эти команды:
первый preflight обязан выявить stale metadata; второй scanner создаёт точную
manifest по уже сгенерированному графу. Ошибки UNKNOWN не игнорировать.
