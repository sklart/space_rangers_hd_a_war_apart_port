## E2E-3 targeted reachability (2026-10-11)

- `TGalaxy::XorProtectedState` is reached by `aSaveLoad` memory-snapshot obfuscation/restoration and by galaxy cleanup if protected state remains. Its `uint32_t` pointer casts and four-byte VMT/field skips are confirmed unsafe for ARM64. This is a save/snapshot blocker, not a reason to change serialized 32-bit IDs. A correct fix needs a protected-field layout test and matching XOR round-trip across the actual 64-bit object types.
- `aScript.cpp` stores actual star/ship/planet/script-item pointers and function addresses in `lvDword`/32-bit signatures. `fGameSettings::TThreadCreateNewGame_Execute` calls `aScript::RunGlobalScriptsForContext` at the end of generation, so script pointer truncation is potentially on the new-game path. An address/token map or pointer-safe script value needs a focused script-binding regression before mutation.
- The `aSaveLoad` snapshot galaxy token uses the existing E2E source-copy `uintptr_t` fix. This protects one transient pointer but does not establish a snapshot or disk save round-trip.
- ARM64 `long double` has a 113-bit mantissa and is not x87 Extended. No evidence yet establishes compatibility of every raw numeric field in saves; inspect concrete serializer calls before changing the format.

## E2E-4 script value boundary (2026-10-11)

The `aScript.cpp` sites above are only the producers. `aScriptFun.cpp` contains many consumers that cast `av[n]->GetDword()` back to a ship, star, planet, item, missile, or script-object pointer, and many functions return pointers through `SetDword(static_cast<uint32_t>(reinterpret_cast<uintptr_t>(...)))`. For example, `SF_Id` reads a pointer but returns a numeric ID (`aScriptFun.cpp:609-625`), while `SF_IdToPlanet` returns a pointer from a numeric ID (`:1047`). Those two directions need different conversions. A fix only at `RunGlobalScriptsForContext` would leave the function bridge unsafe.

Upstream `TVarEC` stores `DwordValue` as `uint32_t` (`types/EC_Expression.hpp:146-151`). The disposable combined overlay widens this runtime cell and its `GetDword`/`SetDword` interface, selected comparison operands, `TScriptPlace::TargetValue`, and pointer casts at the `aScript`/`aScriptFun` bridge. The original 32-bit integer and DWORD disk fields remain unchanged. A host test checks low numeric values, sign extension and high-address round trips. These checks do not prove the original expression evaluator, script calls, or save/load.

`TScript::SaveState` serializes pointer-bearing `vkDword` cells before writing separate object-ID binding sections. The overlay refuses a value that exceeds the on-disk width rather than silently truncating it, including `TVarEC::SaveToBuffer`. A process-local token table alone would make save/load unsafe unless the serialization and rebinding boundary is handled explicitly. This guard can make a scripted save fail; it does not yet provide a complete save/load solution. `TScriptPlace::TargetValue` is an additional independent narrowing point even if script variables are repaired.

**Implementation gate:** the ordinary build stays unchanged; the combined experiment contains the partial native-width overlay. Before hardware handoff, require a complete producer/consumer manifest, save/load handling of pointer-bearing cells, and host regressions that execute original script binding functions on high addresses. Then run ASan/UBSan, ARM64 link, and original new-game plus save/load checks. The current audit is source evidence, not a script runtime PASS.

### FPC reference boundary

At `pakompom/SpaceRangersHD_FPC@e7a7bdce89d75f64868c438da7464783933d6406`, [`source/script/EC_Expression.pas`](https://github.com/pakompom/SpaceRangersHD_FPC/blob/e7a7bdce89d75f64868c438da7464783933d6406/source/script/EC_Expression.pas) declares `DwordValue: PtrUInt`, `GetDword: PtrUInt`, and `SetDword(Value: PtrUInt)`. [`source/script/aScript.pas`](https://github.com/pakompom/SpaceRangersHD_FPC/blob/e7a7bdce89d75f64868c438da7464783933d6406/source/script/aScript.pas) declares both script state/place target values as `PtrUInt`. This is evidence for native-width **runtime** representation. The same reference still calls `Buffer.AddDWord(Cell.GetDword)` when saving both local-variable scopes, so it does not by itself prove that arbitrary pointer-bearing variables survive save/load. The C++ fix must separately account for persisted values and reject any save that would leave an unresolvable address in the file.
