## E2E-3 targeted reachability (2026-10-11)

- `TGalaxy::XorProtectedState` is reached by `aSaveLoad` memory-snapshot obfuscation/restoration and by galaxy cleanup if protected state remains. Its `uint32_t` pointer casts and four-byte VMT/field skips are confirmed unsafe for ARM64. This is a save/snapshot blocker, not a reason to change serialized 32-bit IDs. A correct fix needs a protected-field layout test and matching XOR round-trip across the actual 64-bit object types.
- `aScript.cpp` stores actual star/ship/planet/script-item pointers and function addresses in `lvDword`/32-bit signatures. `fGameSettings::TThreadCreateNewGame_Execute` calls `aScript::RunGlobalScriptsForContext` at the end of generation, so script pointer truncation is potentially on the new-game path. An address/token map or pointer-safe script value needs a focused script-binding regression before mutation.
- The `aSaveLoad` snapshot galaxy token uses the existing E2E source-copy `uintptr_t` fix. This protects one transient pointer but does not establish a snapshot or disk save round-trip.
- ARM64 `long double` has a 113-bit mantissa and is not x87 Extended. No evidence yet establishes compatibility of every raw numeric field in saves; inspect concrete serializer calls before changing the format.

## E2E-4 script value boundary (2026-10-11)

The `aScript.cpp` sites above are only the producers. `aScriptFun.cpp` contains many consumers that cast `av[n]->GetDword()` back to a ship, star, planet, item, missile, or script-object pointer, and many functions return pointers through `SetDword(static_cast<uint32_t>(reinterpret_cast<uintptr_t>(...)))`. For example, `SF_Id` reads a pointer but returns a numeric ID (`aScriptFun.cpp:609-625`), while `SF_IdToPlanet` returns a pointer from a numeric ID (`:1047`). Those two directions need different conversions. A fix only at `RunGlobalScriptsForContext` would leave the function bridge unsafe.

`TVarEC` stores `DwordValue` as `uint32_t` (`types/EC_Expression.hpp:146-151`). `GetDword`/`SetDword` and expression operators use that width deliberately for numeric values. Changing the type globally would affect arithmetic and the on-disk format. In particular, `TScript::SaveState` serializes pointer-bearing `vkDword` cells before writing the separate object-ID binding sections. A process-local token table alone would therefore make save/load unsafe unless the serialization and rebinding boundary is handled explicitly.

**Implementation gate:** keep the current Audio OFF and Audio ON builds unchanged while this is open. Before an experimental script override is enabled, require a complete producer/consumer manifest, explicit token lifetime and stale-token rejection (or native-width value propagation), save/load handling of pointer-bearing cells, and host regressions that execute original script binding functions on high addresses. Then run ASan/UBSan, ARM64 link, and original new-game plus save/load checks. The current audit is source evidence, not a script runtime PASS.
