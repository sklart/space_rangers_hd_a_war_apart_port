Для первых двух пунктов рядом с NRO: `perf-mode.txt` = `basic`,
`scene-mode.txt` = `on`. Режимы читаются при запуске. В начале
`logs/perf515-stage.log` проверить `build_git=03651ce`.
Имена perf515 сохранены в диагностической инфраструктуре perf516.

1. **Фоны:** новая игра → генерация → персонаж → станция/ангар → карта →
   игровое меню → назад. Снять фото первого чужого фона, записать переход.
   Сохранить журналы и `logs/scene-*.ppm` до следующего запуска.
   Сопоставление `compose-before/after`, capture/background owner и
   `present-input` отличит CPU-подложку от последующего SDL/GPU-вывода.
2. **Карта:** отдельный запуск с копией готового сейва → станция → карта →
   реальный приказ перемещения → завершение хода. Снять короткое видео
   команды и отклика; отметить дату и положение корабля. Смена дня сама по

3. **Сохранение:** на тестовой копии перелететь → сохранить новым именем

4. **Аркада:** перезапустить с `scene-mode.txt` = `off`, `perf-mode.txt` =

   Записать длительность пауз, последний кадр и реакцию ввода. Не считать
   тики FPS; CPU-выигрыш host ещё не измерен на Switch.

Если времени мало, первые три пункта важнее. Для каждого отдельного запуска
сохранить весь `logs/`, включая `perf515.csv`, `perf515-stage.log`,
`port.log`, `port-prev.log`, `gr-main.log`, `e2e.log`, `scene-*.ppm`, если
они созданы. В диагностическом профиле часть сообщений перенаправляется в
stage log; отсутствие отдельного файла не означает отсутствие события.
Снимки ограничены 48 файлами за запуск и не являются GPU readback.

Приложить ZIP логов, SHA-256 NRO, фото/видео, последовательность действий,
режим handheld/docked и способ завершения. Не включать игровые ресурсы и
исходные пользовательские сейвы. При аварии сохранить соответствующий
crash report; после принудительного выхода хвост буферизованного лога может
отсутствовать. Подробнее: `docs/e2e515-hardware-followup-test.md`.

## MatrixGame: отдельный существующий GPU smoke

После основной игры, отдельным запуском. Комплект
`build/e2e515/hardware-gpu-a224fa4.zip`, source Git SHA
`a224fa476704bc65a47049d0ede1b2123fe484a9`.
SHA-256 ZIP: `1c5cfebb2696bbf6db98bd2cd598956f468ef1ca8183bbf31271148c30103429`.

- `matrixgame-gpu-smoke.nro`: `e984feaeee119e2599419210f9e3840980a510ec7e671629fcf361f694d01432`.
- Matching ELF: `1bcb7a2977a28555aad13f2e7ac14db6bbd1aec0cfa436b4989b91c25fb939af`.
- Build ID: `41f3eaf0b062b3d730130538bb79f151d93345df`.

Скопировать его `switch/matrixgame-deko-smoke/` отдельно от основной игры.
В приватном комплекте уже есть `model.vo` (wood05, 103 вершины/240 индексов).
Не публиковать эту модель. Запустить `MatrixGame real VO GPU smoke`.
Он проверяет настоящие VO/BigVB/BigIB → upload → indexed draw → readback
64×64 → повторный draw и release/recreate. Это белый материал, отдельная
камера, без боя. Новый CPU-срез CVectorObject E2E-5.17 в эту старую NRO не входит.

Снять итог PASS/FAIL, сохранить
`sdmc:/switch/matrixgame-deko-smoke/gpu-smoke.log`, выйти кнопкой B.
Один BEGIN без END status=PASS успехом не считается. GPU PASS относится
только к этому smoke, не к CGame::Init/RunGameLoop или планетарному бою.
Сейчас оба аппаратных сценария имеют статус **HARDWARE PENDING**.
