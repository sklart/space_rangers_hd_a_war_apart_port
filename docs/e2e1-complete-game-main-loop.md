## Current software findings

- A direct devkitA64 pass compiled all 297 upstream `src/*.cpp` units, including `Rangers.cpp`, with no source compile error. This verifies translation-unit compilation only. `runtime/runtime.cpp` also compiled. The dedicated `switch-e2e-game` target now attempts the complete set and writes `e2e-build-report.json` on failure or success.
- The first raw link of non-PIE objects stopped at `read-only segment has dynamic relocations`; these were rebuilt with `-fPIE`. The complete E2E target compiles **298 upstream units**, replaces the original `EC_HsFile.cpp` implementation with the portable `ec_file_adapter.cpp` at link time, and links **356 objects** plus no-TLS OKGF/SoftFloat into an ELF64 AArch64 PIE with **zero undefined symbols**. Four old diagnostic shim objects had duplicate definitions and are not linked. A build-integrity correction was necessary: the first disposable-copy `git apply` did not change GR_Main/DAT, despite returning success. The builder now asserts that the renderer patch is present; the corrected link first exposed missing OKGF symbols, then passed after the ARM64 libraries were added. The linked ELF still contains 14 exact DLL names, so the dependency audit fails. Presence of a DLL name is an executable-image finding; it does not by itself prove a particular startup call is reached.
- QPC now returns the Switch system counter with `armGetSystemTickFreq()` from that same counter; host uses steady-clock nanoseconds with frequency 1,000,000,000. `GetTickCount` and original `MMSystem::timeGetTime` return milliseconds. `Sleep` performs a real wait or zero-duration yield. The host timing test passed; the modified platform source and generated original API overrides compile and link for ARM64.
- The build report enumerates the current OPTIONAL platform bypasses: single-instance lookup, HKLM registry write, Wine and Steam detection, timer-resolution requests, thread scheduling priority, COM cleanup, and the executable-path branch already handled by the E2E entrypoint. Original sound and music are explicitly disabled before the original sound manager is created, and the DirectSound enumeration/WinMM audio timer wrappers are inert; this is allowed for the first menu run and removed `dsound.dll` and `winmm.dll` from the ELF. The report lists no REQUIRED stubs. This is a code audit, not a runtime claim.
- A full exact-name scan found 14 DLL names in the ELF, including `advapi32.dll`, `matrixgame.dll`, `okgf.dll`, `ole32.dll`, and `shell32.dll`; the earlier seven-name audit undercounted them. Each name is an image finding, not proof of a reached runtime call. The original script-host startup creates several synchronization events and a suspended worker thread. Portable events and worker threads now preserve create, signal, reset, wait, resume and close semantics; host tests and ARM64 compile/link pass. The original runtime path remains unverified until the game runs. `GR_Main` now queries actual process memory through libnx for its cache budget, uses the SDL window for geometry/focus, and copies the initial CFG.TXT through the resolved game and user paths.
- devkitA64 reports `sizeof(long double)=16`, `alignof(long double)=16`, `LDBL_MANT_DIG=113`, `LDBL_MAX_EXP=16384` (macro read plus compiled static assertions). This is binary128 and cannot be assumed to match serialized x87 Extended data. The `Extended` inventory and conversion policy remain open.
- The pointer-width scan found 356 pointer-to-`uint32_t` cast lines in 20 original source files. In `aGalaxy.cpp`, `TGalaxy::XorProtectedState` uses truncated object addresses for its XOR ranges and exclusions (`Data`, `Excluded`, `Exclusions`), and `XorStateBytes` advances a pointer through a 32-bit intermediate. These are confirmed ARM64 hazards in the galaxy protected-state path; other cast sites include serialized 32-bit IDs and still require classification. No pointer-width fix is claimed yet.
- A read-only FPC platform comparison is in [`e2e-fpc-reference.md`](e2e-fpc-reference.md). Its script DLL bridge explicitly rejects non-Win32 imports, so it does not establish a working ARM64 script host.

## Runtime status

`ProgramMain` **NOT ENTERED**. Forms, platform runtime, language/packages, script host, runtime/settings, global UI, robot runtime, screen loop, real menu, original input action and gameplay are **NOT TESTED** in E2E. The old M27 diagnostic NRO is not reused as evidence for those stages.

The build now packages an **experimental** E2E NRO even when the dependency audit fails, with its byte count, SHA-256 and embedded `build_git` recorded in `e2e-build-report.json`. It is a diagnostic artifact, not an E2E hardware PASS. The build ID receives `-dirty` when tracked source edits or untracked files are present, excluding the generated report itself.

The original main-screen state logic is present in `Rangers.cpp`: it sets `RequestedScreenId=screenLoad` and calls `RunMainScreenStateLoop()` after settings, global UI and robot initialization. E2E must execute that sequence rather than manually loading a `Main.dat` subtree.

Existing M12–M27 regression gates remain available independently of the E2E target. The observed failure queue is in [`e2e-observed-blockers.md`](e2e-observed-blockers.md).

The next E2E job exposed `fatal: detected dubious ownership` during Git provenance lookup inside the container. The workflow now trusts its exact checkout and submodule paths before building; that fix awaits a new CI run. The local E2E target currently fails at the known Windows DLL image audit.
