This verifies translation-unit compilation only. `runtime/runtime.cpp` also compiled. The dedicated `switch-e2e-game` target now attempts the complete set and writes `e2e-build-report.json` on failure or success.

The complete E2E target compiles **298 upstream units**, replaces the original `EC_HsFile.cpp` implementation with the portable `ec_file_adapter.cpp` at link time, and links **356 objects** plus no-TLS OKGF/SoftFloat into an ELF64 AArch64 PIE with **zero undefined symbols**. Four old diagnostic shim objects had duplicate definitions and are not linked. The builder now asserts that the renderer patch is present; the corrected link first exposed missing OKGF symbols, then passed after the ARM64 libraries were added. The linked ELF still contains 14 exact DLL names, so the dependency audit fails. Presence of a DLL name is an executable-image finding; it does not by itself prove a particular startup call is reached.
- QPC now returns the Switch system counter with `armGetSystemTickFreq()` from that same counter; host uses steady-clock nanoseconds with frequency 1,000,000,000. `GetTickCount` and original `MMSystem::timeGetTime` return milliseconds. `Sleep` performs a real wait or zero-duration yield. The host timing test passed; the modified platform source and generated original API overrides compile and link for ARM64.
- The build report enumerates the current OPTIONAL platform bypasses: single-instance lookup, HKLM registry write, Wine and Steam detection, timer-resolution requests, thread scheduling priority, COM cleanup, and the executable-path branch already handled by the E2E entrypoint. Original sound and music are explicitly disabled before the original sound manager is created, and the DirectSound enumeration/WinMM audio timer wrappers are inert; this is allowed for the first menu run and removed `dsound.dll` and `winmm.dll` from the ELF. - A full exact-name scan found 14 DLL names in the ELF, including `advapi32.dll`, `matrixgame.dll`, `okgf.dll`, `ole32.dll`, and `shell32.dll`; the earlier seven-name audit undercounted them. Each name is an image finding, not proof of a reached runtime call. The original script-host startup creates several synchronization events and a suspended worker thread. Portable events and worker threads now preserve create, signal, reset, wait, resume and close semantics; host tests and ARM64 compile/link pass. The original runtime path remains unverified until the game runs. `GR_Main` now queries actual process memory through libnx for its cache budget, uses the SDL window for geometry/focus, and copies the initial CFG.TXT through the resolved game and user paths.

- The pointer-width scan found 356 pointer-to-`uint32_t` cast lines in 20 original source files. In `aGalaxy.cpp`, `TGalaxy::XorProtectedState` uses truncated object addresses for its XOR ranges and exclusions (`Data`, `Excluded`, `Exclusions`), and `XorStateBytes` advances a pointer through a 32-bit intermediate. These are confirmed ARM64 hazards in the galaxy protected-state path; other cast sites include serialized 32-bit IDs and still require classification. No pointer-width fix is claimed yet.
- A read-only FPC platform comparison is in [`e2e-fpc-reference.md`](e2e-fpc-reference.md). Its script DLL bridge explicitly rejects non-Win32 imports, so it does not establish a working ARM64 script host.

## Build and source integrity

`tools/e2e_arm64_build.py` compiles into `port/switch/build/e2e-game`; narrow overrides are generated by `tools/e2e_source_overrides.py`. Neither script applies or reverses patches in `upstream/cpp`. The host CI's three portability patches target disposable source copies. The older diagnostic Makefile now refreshes `src/` and `runtime/` into `port/switch/build/disposable-cpp` before its recipes, and all its patch commands target that copy. Its patch-using recipes remain serial because they share the copy. A real host EC_File test passed through the changed Makefile; the patched GR_Main, EC_BlockPar and EC_Data ARM64 objects compiled. In an interrupted-patch simulation, the patch changed only the disposable GR_Main, the next preparation restored it byte-for-byte from upstream, and `upstream/cpp` remained clean. This proves the tested paths' interruption safety, not every Make target's runtime behavior. Existing M12–M27 regression gates remain available independently of the E2E target. The observed failure queue is in [`e2e-observed-blockers.md`](e2e-observed-blockers.md).

CI has an `e2e-full-arm64-link` job in the official devkitA64 container and retains the host regression job. The first observed GitHub run passed host regression and failed the E2E job. A later run exposed `fatal: detected dubious ownership` during Git provenance lookup inside the container; after trusting exact checkout paths, the container compiled and linked the full target, then failed at the same 14-name DLL audit as the local build. Run `37919934488` completed with host regression success. Its E2E job compiled and linked, then failed at the same 14-name ELF dependency audit.
