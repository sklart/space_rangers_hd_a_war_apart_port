# E2E-5.15: первый аппаратный прогон

Принято последующее дополнение о performance diagnostics. Подготовлена
самостоятельная диагностическая NRO; исходный комплект ниже остаётся
неизменным. Для приоритетного CPU/GPU/RAM прогона использовать
[новую инструкцию](../../docs/e2e515-performance-diagnostics.md) и
[комплект с хэшами](e2e515-performance-preparation.md).

20.10.2026. Физическая Switch доступна. Приоритет изменён: текущая Release
Save ON основной игры → первый аппаратный прогон → разбор подтверждённых P0.
Новые этапы оптимизации и переноса MatrixGame до разбора результатов не начинать.
Push не разрешён. Аппаратные результаты пока не получены.

## Зафиксированная база

Незавершённые BigVB/BigIB и deko3d сохранены отдельным локальным коммитом
`7d3b4f5566e41d4d1b29fa8f0770e22aa2d06ee5`. Четыре адресные проверки CPU прошли
с ASan/UBSan/leak detection. Контрольный transcript и три реальные VO-модели
дают одинаковые SHA на native host, оригинальном Windows D3D9 и ARM64/QEMU.
Это не подтверждает работу GPU или полноценного боя.

Основной build использует `tools/e2e_arm64_build.py --profile release
--experimental-e2e4-combined --enable-experimental-saves`: полный оригинальный
игровой код, Audio ON, RSG64/v168, запись на диск включена. Экспериментальный
`port/matrixgame/deko` и native-core в этот link не подключаются. Сохраняется
существующая граница недоступного планетарного боя.

Исходные пользовательские сейвы, `saves/`, G:/pack*.zip и существующий untracked
отчёт не коммитятся и не переписываются. Проверка восьми исходных файлов PASS.
Перед новым прогоном скопировать прежние логи и весь каталог config с SD на ПК.

## Установка и сбор материалов

Основной комплект: `build/e2e515/hardware-main-7d3b4f5.zip`.
В нём скопировать папку `switch` в корень SD: устанавливается только
`switch/space-rangers-hd-a-war-apart/SpaceRangersHD-E2E515.nro`, без config/сейвов.
Использовать NRO с его SHA256SUMS и manifest.json.
Matching ELF из debug оставить на ПК для расшифровки ошибок. Данные игры оставить в существующем
`sdmc:/switch/space-rangers-hd-a-war-apart/`; каталоги сохранений не переносить.
NRO запускать из hbmenu в режиме приложения с полным доступом к памяти
(title override), записав способ запуска. Не использовать applet mode для
сравнения производительности и доступной памяти.

Сохранения проверять на копии прежнего config/Save (с фактическим регистром
каталога SD). Основные оригиналы до прогона скопировать на ПК. Новый v168 с
item-kind15 после перелёта может не читаться старыми сборками порта; загрузку
проверять этой же NRO. Совместимость с Windows v167 не заявляется.

После завершения штатно выйти через пункт игры, дождаться возврата в hbmenu,
затем скопировать весь `switch/space-rangers-hd-a-war-apart/logs/` с SD,
включая e2e.log и scene-*.ppm. e2e.log дописывается: прежний лог заранее
сохранить отдельно. При зависании записать время, последний видимый экран,
длительность ожидания и способ завершения; сохранить доступные crash reports.
Логи буферизуются, поэтому после принудительного завершения хвост может
отсутствовать. Не очищать SD и не удалять исходные сохранения ради диагностики.

Приложить короткое видео обычного боя до взрыва и момента задержки, способ
запуска, handheld/docked, контроллер, версию системы, настройки звука/графики,
имя загруженной копии сейва и последовательность действий. Логи и сейвы
передаются приватно; в Git их не добавлять.

## Проверки по приоритету

1. **P0, аркада:** 60–90 секунд обычного боя с движением, стрельбой,
   столкновениями и взрывами; затем пауза/возврат и ещё 30 секунд. Проблема —
   постоянная медленная работа всего боя; взрыв с задержкой около 40 секунд
   является крайним проявлением. Отметить реакцию на стик/ZR, темп движения,
   выстрелов и урон. Второй короткий прогон той же сцены с громкостью 0 нужен
   только как сравнение слышимого звука: mute не доказывает отключение декодера.
2. **P0, фон:** генерация → персонаж → ангар → карта → станция/магазин → меню
   → назад. На подозрительном экране подождать 10 секунд, сделать снимок.
   Для полноценных scene-60 samples экран должен выполнить 60 презентаций;
   10 секунд сами по себе этого не гарантируют. Не принимать нормальный
   полупрозрачный фон родительского экрана за остаток генерации.
3. **P1, ввод:** Hybrid и Cursor, D-pad/стики, L3, R3, A/B/Y, открытие
   диалога при удержании кнопки, отпускание после закрытия, + пауза и B возврат
   в аркаде. OSK: кириллическое имя, подтверждение, повторное открытие/отмена,
   возврат без повторного клика. Проверить HOME/возврат и переподключение
   контроллера. Полная справочная раскладка: docs/switch-controller-controls.md.
4. **P1, сейв:** загрузить копию → перелететь к другой звезде → сохранить
   отдельным именем «Перелёт Ёж» → штатно завершить → снова запустить ту же
   NRO → загрузить новый слот и сверить звезду/ход/корабль. При отказе сохранить
   сообщение, логи, временный/recovered файл и имена файлов каталога.

## Что уже измеряет NRO

| Маркер | Назначение и граница |
|---|---|
| `build_git=` | Идентификатор текущего исходного кода; проверить до сценариев |
| `presentation rate` | Реальные завершённые SDL Present, FPS за окно и среднее/max времени presentation path |
| `perf source=present stage=40..45` | Подготовка/загрузка/copy/Present/полный путь/интервал между завершёнными Present |
| `perf source=detail stage=46/47` | DrawFrame / TimerTakt аркады; микросекунды, count, p50/p95/p99/max |
| `perf source=arcade-phase stage=2` | Обход Obj->Advance вместе с сопутствующей работой участка; не отдельный GPU time |
| `arcade-phase stage=3/4/5/6` | Подготовка изображений, world lines/images, UpdateVisuals, repel overlaps |
| `arcade timer debt` | Долг и фактически доставленные миллисекундные callbacks последнего sampled batch; не число 20-мс логических тиков каждого кадра |
| `perf audio cumulative` / `perf log cumulative` | Затраты источника/декодирования звука и собственно записи логов |
| `scene canvas` / `scene background captured` | Вложенность, наследование Aux/подложки, source/prepared hashes |
| `screen first presented` / `scene-*.ppm` | Hash и уменьшенные снимки опубликованного RGB565 framebuffer |

Эти данные отделяют медленную симуляцию от подготовки графики и ожидания Present.
Время функций — wall time, не аппаратный CPU/GPU счётчик. GPU timer queries,
точная задержка кнопка→игровое событие и лог каждого тика на каждом кадре пока
отсутствуют. Видео помогает сопоставить событие с логом. CPU-фазы внутри
TimerTakt вложены: их время нельзя складывать с полным TimerTakt.
Перцентили считаются по ограниченному окну до 128 samples, count/avg/max —
по всем samples окна; это не полная трасса каждого кадра.

Хэши source/prepared/present и PPM позволяют проверить подложку и опубликованный
кадр. Точные пиксели каждого отдельного UI-cache leaf автоматически не снимаются:
если оба слоя корректны, а артефакт сохраняется, потребуется адресная проверка
контрола по первому аппаратному примеру.

## Отдельный MatrixGame GPU smoke

Необязательный комплект `build/e2e515/hardware-gpu-a224fa4.zip`; source SHA
`a224fa476704bc65a47049d0ede1b2123fe484a9`, Build ID
`41f3eaf0b062b3d730130538bb79f151d93345df`. Это маленькая обёртка уже существующего
probe, без нового этапа движка. Первая линковка не нашла /opt/devkitpro/switch.ld
из-за отсутствующего DEVKITPRO в shell; повтор с C:/devkitPro успешно завершён.
Для воспроизведения configure использовать существующий deko CMake/toolchain,
`-DMATRIXGAME_SMOKE_GIT=<source SHA>`, target `matrixgame-gpu-smoke`, затем
nacptool/elf2nro и независимую проверку matching Build ID.

Скопировать его папку switch в корень SD отдельно от основного комплекта.
Запустить `MatrixGame real VO GPU smoke` из hbmenu в режиме приложения.
В комплекте приватная копия настоящей Matrix/Obj/tree/wood05.vo: 103 вершины,
240 индексов, source SHA
`04497dcc94ede26f183d847a4dd094d3ba05bc825d09fcfa73fa36bfae80981e`.
Ресурс остаётся только в ignored build/ZIP, не публикуется в Git.

Проверка запускается один раз: CStorage/VO → оригинальные BigVB/BigIB → GPU
буферы → настоящий indexed draw → readback 64x64 → ненулевой кадр → повторный
draw/cache → release/recreate и равенство результата. Это отдельная камера,
белый материал, без текстур и сцены боя. Полученные stdout/stderr сохраняются
в `sdmc:/switch/matrixgame-deko-smoke/gpu-smoke.log`; лог дописывается.
PASS/FAIL виден на экране; B закрывает приложение. Передать этот лог и фото.
Одного BEGIN без END status=PASS недостаточно. При зависании сохранить лог;
основной аппаратный прогон имеет приоритет. GPU execution пока PENDING.
