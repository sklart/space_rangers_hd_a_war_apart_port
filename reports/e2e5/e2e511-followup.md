## Управление аркадой

| Кнопка | Действие |
| --- | --- |
| Левый стик | Направление и тяга |
| Правый стик | Курсор |
| Крестовина | Прежние дискретные команды движения |
| ZR / ZL | Основной / дополнительный огонь |
| L | Следующее основное оружие |
| R | Следующее дополнительное оружие |
| − | Автопилот / ручное управление |
| A по значку оружия | Изменение его группы, как в оригинальном интерфейсе |
| X / Y | Enter / Escape |
| + | Выход из приложения |

Чтение триггеров отделено от флага экспериментальных сохранений.
Отключение дисковых сохранений больше не отключает ZL/ZR.
Сочетание ZL+ZR+− остаётся зарезервированным; F5 на Switch при отключённом
эксперименте не доставляется. Новые команды доставляются один раз на нажатие,
освобождаются при смене режима и не действуют как аркадные вне аркады.
Пустая группа оружия не меняет выбор, обход ограничен пятью слотами.
Движение левым стиком обновляет таймер последнего ручного ввода и снимает
автопилот; состояние его кнопки обновляется только при переключении.

Подсказки оружия и автопилота показывают кнопки Switch. Подсказка входа
в сгусток использует X; подсказки кнопок полёта/остановки предлагают A
по кнопке под курсором. Остальные режимы не объявляются полностью
адаптированными к контроллеру.

## Задержки и диагностика

Путь touch-прокрутки карты больше не использует синхронный scroll-blit
`pstView`: смещение обновляется через `pstAll` с отложенной перерисовкой.
Прежний режим панели восстанавливается даже при исключении.
Приказ кораблю по-прежнему выдаётся только после отпускания короткого касания.
Эффект на задержки Switch ещё требует измерения.

Вложенные циклы теперь записывают имя окна и прохождение геометрии,
границ и активации, код выхода и запрошенный переход. Для фоновых контролов
записываются путь, активность, границы и действующий backend. Этапы открытия
сбрасываются на диск сразу; постоянного сброса на каждом кадре нет.
Опциональный host-захват сохраняет настоящие кадры
в PPM из UI-потока; он отсутствует в Switch-сборке.

При `E2E5_DISABLE_DISK_SAVE=1` меню теперь пропускает построение миниатюры
галактики. Обычный снимок текущего экрана сохраняется; уже выделенный второй
preview заполняется нулями. В сборках с разрешённой записью сохраняется
прежний путь создания обеих миниатюр. Устранена ненужная скрытая работа
на найденном пути открытия меню, а не объявлен исправленным любой возможный
механизм зависания при перелётах.

Настоящий host UI с конфигурацией из архива показал правильный фон станции.
Ресурс `Bm.FormRuins.2RCbg` на host и в аппаратном журнале имеет одинаковые
размеры входного буфера/геометрию: 5968179 байт, 1920×1536, после обработки
1843296 байт. Это сопоставление размеров, а не проверка побайтовой идентичности
SD-ресурса. Аппаратный дефект чужого фона остаётся открытым.

## Качество и многоядерность

`MultiThread` исходной игры выбирает Win32 process affinity. В Switch-порте
этот путь не применяется; загрузчик и расчётные потоки уже используют
отдельное разрешённое ядро. Изменение галочки не включает новый алгоритм
параллельного расчёта галактики. `HardwareRender=True` в CFG также не означает
наличие D3D9-рендера: порт использует программный framebuffer.

Максимум эффектов не установлен обязательным профилем. Расчёт галактики
остаётся отдельной стоимостью; туманности, шлейфы и анимация добавляют расходы
отрисовки. Сначала нужны воспроизводимый базовый профиль и стабильность,
затем отдельные измерения каждого эффекта. Это вывод из кода порта и
аппаратных замеров, а не обещание ускорения переключением настройки.
