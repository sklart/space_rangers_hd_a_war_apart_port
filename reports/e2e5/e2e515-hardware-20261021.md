## Сохранения: подтверждённый отказ и адресное исправление

Четыре раза текущий stage-log фиксирует `retain-failed-save: copy or flush
failed: Function not implemented`. В архиве остаётся непустой save.tmp и
четыре нулевых RecoveredSave-N.sav. Отказ происходит в `copy_file` до вызова
SyncFile; имя слота и кириллица не объясняют этот отказ.

В установленном devkitA64 r30-1 / GCC 16.1.0 / libnx 4.12.0-1
дизассемблирование libstdc++.a подтверждает вызов fchmod из do_copy_file.
У libnx fsdev_fchmod возвращает ENOSYS. Адресный host-тест с экспортированной
реализацией fchmod, возвращающей ENOSYS, воспроизводит тот же пустой выходной
файл у настоящего std::filesystem::copy_file.

Коммит `f5cb46fd3b28102ffadf45807821907380229bce` заменяет POSIX byte-copy на
ограниченный 32-КиБ буфер с эксклюзивным созданием O_EXCL, без копирования
permission metadata. Windows сохраняет прежний механизм. Не отключены
fsync, CRC/size readback, запрет перезаписи, сохранение исходного temp при
ошибке. Нулевые старые recovery-файлы не удаляются и не перезаписываются.

Проверки на копиях аппаратных AutoSave.sav и save.tmp:

- PASS ASan/UBSan: ENOSYS у старого copy_file, сохранение байтов новым путём,
  обход занятого recovery-слота, реальный отказ fsync и успешная повторная
  попытка с неизменным исходным файлом.
- PASS ASan/UBSan: 18 возвратных ошибок, 18 прерываний процесса, 36 повторных
  попыток, 3 прерывания при создании нового слота; латиница и кириллица.
- PASS Release ARM64, Save ON, Audio ON, matching NRO/ELF, undefined symbols=0.
- HARDWARE PENDING: повторная запись на SD Switch и загрузка после перезапуска.

## Фоны и выход на карту

Фотографии подтверждают остатки текста генерации за новыми интерфейсами.
В логах RuinsTalk, GoodsShop и StarMap открываются с отдельным canvas,
inherit=0, nested=0; старой aux-подложки при входе нет. Реально выбран
software rendering, несмотря на HardwareRender=True в конфиге. Поэтому
очередное обнуление canvas или изменение этого флага не считается решением.

На screen=16 зарегистрировано 4522 выведенных кадра: p50 интервала 18.497 мс,
p95 24.570 мс, максимум 666.910 мс при входе. За пятисекундные окна — около
45–54 Present/с с меняющимися хэшами. Это исключает полную остановку
presentation в записанном участке, но не исключает застывший слой карты,
неверную подложку или UI-кэш при продолжающемся выводе курсора/интерфейса.
Первопричина этого P0 пока не установлена; исправление фонов не заявляется.

Повторён host-маршрут с копией аппаратного CFG: генерация → персонаж → ангар
→ карта → корабль → меню → подтверждение выхода → отмена → карта.
Run `8b923c72fdb4451d80447d148dbe9533`, host ELF
`63e8d10c4036687afe697620ee69f76dca76a7e89b33699e22660e6ab0e5bcc2`.
10 запрошенных кадров прошли сверку RGB565 hash; анализ точных 64×64
фрагментов генерации и восстановление боковых областей меню PASS. Контактный
лист просмотрен: остатки текста на этом host-маршруте не воспроизвелись.
Это другая генерация и ресурсы host-установки, не точное воспроизведение
аппаратной партии. Процесс остановлен runner после проверок; штатный выход
этого host-маршрута не проверен. Конфиги-источники неизменны.
