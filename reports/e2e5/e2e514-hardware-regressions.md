## Подтверждённые симптомы

* Аркада: TimerTakt обычно 25–70 мс при требуемом шаге 20 мс, отдельные
  callbacks свыше 160 мс. В логе 2 показа за 12329 мс, затем 1 за 20608 мс.
  SDL present порядка 7–14 мс не объясняет зависание: старый цикл отрабатывает
  весь FrameTime + CarryTicks, а стоимость этой серии создаёт ещё больший долг.
* Сейв: два `manual save destination missing after replace`, затем отказ
  install rename с восстановлением старого файла; оставшийся `save.tmp`
  блокирует следующие попытки (`occupied temp or unsafe directory`).
  Поэтому смена имени на латиницу после первого отказа уже не помогает.
  В этом архиве нет сообщения `unknown script values` как причины отказа.
* Фон: пользователь подтверждает регрессию на устройстве. По точным
  CFG/Lang/newgame из архива host снова показывает правильные сцены.
  Первопричина конкретного аппаратного изображения пока **не подтверждена**.

## Изменения игрового кода

| Файл / участок | Правка |
| --- | --- |
| `continuous_time.hpp`, `GI_MessageLoop::RunContinuous` через override | Долг хранится между кадрами в uint64; серия уступает управление после превышения бюджета 8 мс, только между callbacks. Каждый логический миллисекундный шаг сохраняется. Следующий внешний цикл опрашивает ввод и рисует кадр. Политика film сохранена. |
| `renderer_platform::SceneCanvas`, тот же loop | Время дочернего Run учитывается у непосредственного родителя и исключается из FrameTime/CarryTicks. Время диалога не становится долгом аркады; вложенность не суммируется дважды. |
| `renderer_platform::SceneCanvas`, входы Run/RunContinuous | Помимо framebuffer изолирован Aux: стабильный объект на экран/глубину, чтобы внешние BGBuf не оставались с освобождённым указателем. Новая самостоятельная сцена получает пустую собственную подложку, overlay — актуальный снимок родителя; при возврате восстанавливаются оба указателя. Известные самостоятельные сцены не определяются только наличием BGBuf. |
| `user_root::ResolveConfigPath` | Физическое имя Save/save выбирается по перечислению каталога, без предположения о надёжной inode-идентичности двух вариантов написания. Переноса пользовательских файлов нет. |
| `e2e4_quicksave_transaction::ReplaceGameSavePath` | Публикация через проверенные copy/flush/readback/size+CRC с сохранением старого поколения, а не доверие одному rename. При отказе запись откатывается, новый temp сохраняется. Это устраняет зависимость данного пути от наблюдавшегося отказа rename; точный errno старого вызова в архиве не записан. |
| `PrepareGameTemp`, TSaver перед CreateNew | Занятый обычный temp сначала побайтно копируется и проверяется, лишь затем освобождается исходное имя. Валидная запись получает `RecoveredSave-N.sav` и видна в списке; незавершённые байты сохраняются как `.tmp`. Каталоги/ссылки/нечитаемые файлы не удаляются. |

50 тиков/с при CPU-стоимости одного тика более 20 мс этой правкой не обеспечены.
Долг не теряется и виден в редком маркере `arcade timer debt`; при длительной
перегрузке отставание игрового времени возможно. Изменение устраняет длинную
непрерывную серию без ввода/кадров, а не объявляет CPU аркады оптимизированным.
Атомарность rename не приписывается копированию: старое поколение сохраняется
отдельно до удаления, при ошибке выполняется проверенный rollback. При обрыве
питания резервный файл остаётся источником восстановления.
