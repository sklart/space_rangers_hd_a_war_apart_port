## Готовое исправление сейвов проверено первым

Не пересобирался и не заменялся архив `hardware-perf515-save-f5cb46f.zip`.
Проверены CRC ZIP, каждый SHA256SUMS, source_commit
`f5cb46fd3b28102ffadf45807821907380229bce`, Save ON и matching Build ID
`80d96dc49060a48f63df1affcb02e687b794f710`.
В самом matching ELF по адресу 0x663340 находится CopyBytesExclusive:
дизассемблирование подтверждает open/fdopen/fwrite вместо copy_file.
Хэш исходника транзакции соответствует source-sha256.json в архиве.

Краткий безопасный сценарий передан пользователю отдельно от разработки:
резервная копия config/Save → загрузка тестовой копии после перелёта → новое
русское имя → ход/перелёт → повторная запись → штатный выход → новый запуск
→ загрузка с проверкой даты/системы/корабля. При ошибке сохранить весь
тестовый config/Save, включая save.tmp/.bak/recovery, и logs.
Инструкция также включена в [README-test](../../docs/e2e515-hardware-followup-test.md).

В начале работы `e2e515_data_baseline.py` подтвердил SHA восьми исходных
пользовательских файлов. Извлечённые аппаратные материалы остаются в ignored
build; оригинальные saves/, G:/pack.zip, D:/logs.zip и MP4 не изменялись.
Старый untracked e2e510-artifact-provenance.json и saves/ не включались в commit.

## Проверен фактический effective ARM64-код

Источники выбраны через effective-source-map.json, а не по наличию текста
в Python override или промежуточной source-overlay:

- GI_MessageLoop и GR_Main — generated-perf; StarMap — generated-perf после
  добавления диагностических hooks; GR_GraphBuf/GI_GraphBuf — generated-perf.
- Run/RunContinuous создают scope canvas до OnOpen и оригинального push,
  сохраняют владельца на весь цикл, освобождают per-loop saved pixels/lines.
- У самостоятельного экрана отдельный canvas; у вложенного окна копия
  родителя, возврат восстанавливает живой parent canvas. Aux имеет стабильный
  адрес для заимствующих BGBuf; capture хранит подготовленный снимок владельца.
- StarMap вызывает RedrawMap, восстановление saved pixels/lines, фоновую
  отрисовку по update rects, Prepare/DrawQueuedControlRects/CommitFrameDraw.
  Лишь после этого EndFramePresentation передаёт текущий буфер в SDL.
- SDL_UpdateTexture обновляет весь RGB565-буфер; дополнительная полная очистка
  кадра, отключение кэша и принудительная полная перерисовка не добавлялись.

## Диагностический кандидат

Код: `e594e5dd9e77defad971a46fa3885f0c30108d00`.
Это наблюдение, а не заявленное исправление графического P0.
Включение: perf-mode.txt=basic и отдельный scene-mode.txt=on рядом с NRO.
По умолчанию scene diagnostics выключены; off отключает их без пересборки.

События: scene-enter/exit, background-capture/restore, frame-compose,
ui-cache-bind/draw, day-accepted, turn-film-start/stop, map-state-observed,
map-state и load-from-screen-failed. Последняя метка раскрывает ранее
беззвучный fallback LoadFromScreen, не меняя обработку исключений.
В журнале есть owner, parent, стек, scope generation, buffer/source, размеры,
pitch/bpp, alpha/borrowed, saved pixel/line counts. BGBuf сообщает исходного
владельца stable backdrop, что позволяет проверять повторное чужое заимствование.

До/после композиции и из реального CPU upload input берутся ограниченные
640×360 снимки RGB565. Центр карты, нижняя панель и область курсора имеют
раздельные sample hashes. В сопоставлении кадров объединение двух областей
курсора исключается из центра/панели. Хэш центральной области сам по себе
не исключает курсор; это делает скрипт по изображениям и координатам.

4 RAM-слота, не более 48 PPM/запуск, без ожидания SD со стороны производителя;
при занятости слотов снимок пропускается и считается image_dropped. Файлы
создаёт исключительно writer, с уникальным run prefix и exclusive creation.
Снимки не могут перезаписать существующий файл. Накопленная копия не зависит
от срока жизни исходного framebuffer. Режим может увеличить CPU-затраты на
выбранных кадрах, поэтому для сравнения аркады scene-mode=off.

Скрипт tools/e2e515_scene_analyze.py формирует JSON и таблицу:
изменилось состояние? изменился центр без курсора? изменилась панель?
совпадает compose-after с upload-input того же поколения и кадра?
Результат на дисплее требует пользовательского видео; GPU readback отсутствует.

## Проверки

- PASS: ASan/UBSan producer I/O guard, bounded queue, owned pixel copy,
  overload, writer shutdown; perf detail и off. Нагрузка снимками не приводит
  к ожиданию filesystem на producer.
- PASS: controlled host с фактическим instrumented renderer: независимая
  сцена, compose/upload, capture/restore, пять диалогов/возвратов, BGBuf metadata,
  изоляция чужой сцены. Инструментированы renderer/perf/test; остальные игровые
  объекты не названы full-game sanitizer PASS. Быстрый искусственный маршрут
  переполнил очередь: пропуски отражены в журнале, не скрыты.
- PASS: шесть engine tests, включая scene-canvas и sanitized-scene; runtime-loop,
  screen-context, native-focus, item-references. Sanitized-scene инструментирует
  renderer, GR_Main, GR_GraphBuf, GI_MessageLoop и тест, не всю игру.
- PASS: три теста анализа сцен, в том числе положительный контроль «данные
  обновились, карта неподвижна» и отдельный случай движения только курсора.
- PASS: 11 тестов анализа производительности, включая screen filter,
  накопительный tick counter, временную корреляцию и неизменность inputs.
- PASS: Release ARM64 syntax изменённых модулей renderer/perf/StarMap/
  GI_MessageLoop/GR_GraphBuf/GI_GraphBuf; effective preflight UNKNOWN=0.

Адресный полный host-маршрут с копией аппаратного CFG, run
800d3b436d1b479d857da34830b298e0, дошёл до восстановления меню в пятом цикле,
но завершился timeout тестового драйвера при выборе Resume: это не PASS пяти
полных возвратов. Повторный run c200277a24454fb0b04addcffaae4b46 прошёл
пять полных циклов. Все 34 запрошенных кадра сверены с RGB565 hashes;
во всех пяти циклах области меню после отмены восстановлены без изменений,
вложенный owner проверен. Точных 64×64 фрагментов генерации в проверяемых
областях новых сцен не найдено; положительные контроли срабатывают.
Это HOST NOT REPRODUCED, не аппаратная приёмка и не доказательство отсутствия
всех возможных кэшированных/смещённых/масштабированных остатков. Процесс
остановлен runner после проверок, normal shutdown не заявляется.

Адресно проверена команда на настоящей host-карте после загрузки уже
существующей изолированной копии сейва после перелёта (turn 360, star 5).
Run b96dce24706447b985e4eb83787984ea: исходная PM_EndTurn реально изменила
модель на turn 361. В двух полных кадрах изменились 45717 пикселей центральной
области и 7542 нижней панели. Пара кадров просмотрена: часть центральной
разницы даёт всплывающая подсказка, поэтому эти числа НЕ выданы за доказательство
обновления всех объектов мирового слоя. Файл-источник и CFG неизменны.
Сценарий дополняет проверку модели/команды, не заменяет аппаратную проверку карты.

Извлечённый save.tmp проверен только как read-only источник: отдельная копия
под .sav успешно загрузилась на host (turn 346, planet screen 5), выполнен
один исходный обработчик хода; исходные байты неизменны. Сам input/save.tmp
не переименовывался и не удалялся. В host runner --advance-turns теперь
поддерживает и карту 16; для неё приёмка ждёт фактический номер хода из модели,
а не звук/появление файла/косвенный счётчик UI callbacks.

Последняя строка использует накопительный счётчик, а не количество CSV-строк:
26 потерянных queue records не теряют уже прибавленный tick counter.
Окно включает смену состояний/паузу/результат; это не точная оценка только
активного режима. При целевом 20-мс шаге 50 Гц устойчивое накопление долга
всё равно не позволяет считать темп исправленным.

CPU основного потока подтверждён TimerTakt; Advance 16.713 мс — WALL,
отдельного CPU span в basic нет. Детальные AI/physics/collision scopes есть,
но в данном basic-прогоне не записывались: их доли не выдумываются.
Первый кандидат для исследования — цикл Obj->Advance и вложенные AI/physics,
второй — DrawFrame/подготовка видимых примитивов (~17.87 мс wall). Вложенные
интервалы нельзя складывать. До локализации графических P0 новая оптимизация
аркады не включается; следующая адресная правка допустима только после
агрегированного профиля и детерминированного A/B одинаковых тиков/world/RNG/
геометрии. Рост FPS при продолжающемся backlog не будет принят за успех.
