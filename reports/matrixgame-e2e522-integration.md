# E2E-5.22 — интеграция составных текстур и native frame paths

Дата: 25.10.2026. Статус: **SOFTWARE RESOURCE PASS / FULL NATIVE INIT PARTIAL / SWITCH HARDWARE PENDING**. Итоговые числа и хэши — в [машиночитаемом аудите](matrixgame-e2e522-integration-evidence.json). Этот отчёт обновляет границы E2E-5.21; старые отчёты остаются историческими срезами.

## Результат

Закрыт прежний guard `BuildTexUnions → CBottomTextureUnion::MakeFromBitmap → CTextureManaged::LoadFromBitmap(DXT1,6)`. Общий исходный компоновщик действительно выполнен на HOST и ARM64/QEMU из защищённого `robots.pkg`: карта `Matrix/Map/desert1_3e.cmap`, шесть unions, 1534 bottom records, 23 embedded bitmap. Выполнены оригинальные Copy/Merge/padding loops, созданы типизированные managed textures и настоящие BC1 payloads. CPU upload fixtures обозначены явно и не выдаются за исполнение GPU.

Подключены дополнительные необходимые native операции viewport/cooperative status и Clear/BeginScene/EndScene/Present для приобретённого экранного буфера. Реальные deko команды, upload и владение слинкованы в полной ELF. **Полный native CGame::Init, возврат PrepareMap и первый кадр на Switch не исполнялись.** Следующий известный прямой provider-guard разобранной последовательности — `CGame::ApplyVideoParams → Device::ReadCreationParameters`.

Новая тяжёлая библиотека не добавлена. Native formatted loader повторяет измеренный порядок D3DX: подготовить level zero с FILTER_NONE, сжать его BC1, затем каждый BOX mip строить из предыдущего **сжатого** уровня. Сжатие всех mip из исходного несжатого RGBA дало бы другой контракт. Alpha threshold — 0.5; отдельно проверены значения 0, 127, 128, 255. Край неполного 4×4 блока обрабатывается без выхода за границы.

### Mip layout

| Уровень | Размер | Tight pitch, байт | Block rows | Payload, байт | CPU/DDS offset |
| --- | --- | --- | --- | --- | --- |
| 0 | 1024×1024 | 2048 | 256 | 524288 | 0 |
| 1 | 512×512 | 1024 | 128 | 131072 | 524288 |
| 2 | 256×256 | 512 | 64 | 32768 | 655360 |
| 3 | 128×128 | 256 | 32 | 8192 | 688128 |
| 4 | 64×64 | 128 | 16 | 2048 | 696320 |
| 5 | 32×32 | 64 | 8 | 512 | 698368 |

Итого **698880 байт** на union, **4193280 байт** на шесть цепочек. Это полезный BC1 payload; фактический GPU расход определяет SDK layout и его alignment. CPU/DDS offsets не используются как адреса block-linear GPU image: upload задаёт отдельный mip view и tight source для каждого уровня.

## Владение, ошибки и GPU lifetime

В BuildTexUnions два массива лениво декодированных оригинальных CBitmap теперь имеют RAII владельцев. Если третья загрузка BC1 отказывает, batch rollback немедленно удаляет и две уже опубликованные texture unions. При неуспешной замене отдельного CBottomTextureUnion прежняя текстура остаётся живой; новый кандидат не публикуется. Удерживаемый packet/image переживает release original handle; диапазон arena освобождается после последнего владельца.

Обнаружен и исправлен реальный отрицательный путь: исходный compositor игнорировал bool от LoadFromPNG, а MergeByMask при пустой/короткой маске мог пропустить работу. Теперь false от decoder, отсутствующие pixels, недостаточные размеры или pitch завершают подготовку ошибкой с batch cleanup. Алгоритм смешивания корректных ресурсов не менялся. Четыре варианта (пустой PNG, один байт, корректный PNG 1×1, повреждённый IHDR extent/CRC) проверены через изменение **только загруженного CStorage в памяти**, затем данные восстановлены; защищённый package не записывается.

Другие отрицательные проверки: повреждённый bottom index, обрезанный DDS, короткие строки, неверные dimensions/count/layout/locked upload, budget exhaustion, 21 позиция отказа ordinary new, failed upload/replacement/re-residency, release при удержании packet, повторный rebuild и отсутствие повторного upload для уже Resident texture. Compile error в первоначальной версии нового отрицательного теста (обращение к private SaveInPNG overload) исправлен использованием публичного FilePNG::Write; assertions не ослаблялись.

В deko path range выделяется по действительным getSize/getAlignment. Каждый staging buffer удерживается до queue flush/waitIdle; descriptor и draw packet удерживают ResidentImage. Invalidate снимает ссылки CPU textures на image, сохраняя payload; старый packet продолжает удерживать свою версию. Это проверено CPU ownership tests и SDK compile/link; физическая синхронизация/отказ GPU требует консоли. Автоматический полный ResetPresentation этим методом ещё не реализован.

Clear пересекает прямоугольники с viewport и target, записывает scissor + реальные clear команды, затем восстанавливает full-target scissor; см. [контракт D3D9 Clear](https://learn.microsoft.com/en-us/windows/win32/api/d3d9/nf-d3d9-idirect3ddevice9-clear). Begin/EndScene отражают область сцены, End записывает barrier; Present действительно submit/present/flush/waitIdle. При abort очередь сначала завершается, ещё dequeued image отменяется через nwindowCancelBuffer, затем очищаются команды/packets/state. GPU error возвращает failure, не маскируется успехом.

**Предел нового frame provider:** требуется уже acquired принадлежащий DekoDevice экранный target. Он не создаёт offscreen surfaces, не делает readback и не открывает произвольную сцену во время Init до acquire. Отсутствие двойного Present и переходы состояния проверены CPU тестом; nwindow cancellation и GPU completion — только compile/link.

## Производительность и повторная подготовка

| Исполненный процесс | Подготовка шести unions | Peak process RSS |
| --- | --- | --- |
| HOST Release: только BC1 encode + BOX mips | **344.909 мс** (218.138 encode + 126.771 mips) | **16896 KiB** |
| ARM64/QEMU: только BC1 encode + BOX mips | **14964.665 мс** | **26620 KiB** |
| HOST ASan/UBSan: original compositor + BC1 + независимая DDS/pixel сверка | 3805.648 / 3357.801 мс, два rebuild | **353284 KiB** |
| ARM64/QEMU: original compositor + BC1 + сверка | 18465.796 / 18387.422 мс, два rebuild | **41796 KiB** |

Это единичные адресные замеры, не статистический benchmark; значения включают нагрузку текущего host. Process RSS включает тест, package reader, сверки и runtime; это не VRAM и не исчерпывающая оценка памяти полной игры. ASan quarantine особенно увеличивает HOST RSS. Время compositor включает наблюдатель/чтение эталонов, поэтому не вычитается из codec timing для оценки «цены компоновки». Скорость консоли и FPS не измерялись.

В каждом полном проходе реально декодированы **127 уникальных bitmap: 104 файловых source PNG + 23 embedded bitmap**. Кэш исходных bitmap внутри прохода занимает 1458176 байт полезных pixels; выполнены 1536 progress calls. Повторных decode одного ID в проходе нет. Package reader потоковый с повторным использованием file slots; весь robots.pkg (232546988 байт) целиком в RAM не загружается.

Два намеренных rebuild выполняют оригинальный Clear/Init и снова готовят шесть ресурсов. Обычный повторный Resident не перекодирует и не загружает чистую texture. Постоянный derived BC1 cache не добавлен: измерения QEMU не устанавливают аппаратный bottleneck Switch, а изменение семантики принудительного rebuild без такого основания не требуется.
