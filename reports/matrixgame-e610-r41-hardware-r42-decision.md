# E610 r41. Аппаратный профиль и выбор для r42

Quick Smoke r41 завершил четыре кадра, Interactive — 538 кадров и выход
по `time_limit`. Оба завершились с кодом 0. Проверены build ID, source
SHA256, хешы NRO, непрерывность `seq` и штатное закрытие журналов r40 и
r41. Все восемь пар BGRA-снимков r40/r41 совпали побайтно.

База r40 — `C:/logs7.zip`, SHA256
`0337ccff3caea1eb9bbc53a0425303dab68764bf87d2b477d1a585cbd0ffdc07`.
Архив r41 получен через отдельную NRO по Wi-Fi, SHA256
`883267c1dec7b00a22f62ef760f36a16c443e2e65a0d82ecf596995ca8c170b3`.

## Кадры 60–240

Стенное время вычислено между отметками `original_loop_frames_presented`.
Счётчики взяты как разность двух относящихся к этим отметкам снимков.

| Метрика за 180 видимых кадров | r40 | r41 |
| --- | ---: | ---: |
| Стенное время, с | 37,708 | 38,211 |
| FPS | 4,774 | 4,711 |
| Draw / отправки / drains | 203 580 / 3 240 / 3 060 | 203 580 / 3 240 / 3 060 |
| Создания GPU-блоков | 830 | 830 |
| Draw CPU, с | 19,859 | 19,792 |
| Декодирование вершин, с | 6,564 | 6,636 |
| `waitIdle` в drain, с | 13,808 | 13,887 |
| Ожидание в Present, с | 1,370 | 1,371 |
| Ожидание при acquire, с | 0,056 | 0,056 |
| Журнал, с | 7,214 | 7,663 |
| Записи журнала | 1 287 | 1 329 |
| Байты журнала | 477 857 | 496 248 |

**Ожидание GPU — крупнейшая из двух измеренных статей.** Только drain
занял 36,3% окна, вместе с Present и acquire — 40,1%. Все 3 060 drain
в r41 вызваны лимитом в 64 draw-пакета. Каждый drain имеет один
`waitIdle`, в среднем 4,54 мс. Распределение:

| Длительность одного ожидания | Число |
| --- | ---: |
| До 0,25 мс включительно | 0 |
| Свыше 0,25 до 1 мс | 1 |
| Свыше 1 до 4 мс | 1 268 |
| Свыше 4 до 16 мс | 1 785 |
| Свыше 16 мс | 6 |

Максимум окна — 35,354 мс. Readback, нехватка upload и command backing
не вызвали новых drain на этом участке. Командный backing оставался
2 МиБ. Очередь здорова, SDK warnings равны нулю. В обеих версиях активный
upload достигал 7 933 952 байт к 240-му кадру, пул на этом кадре —
10 481 664 байта. Пик пула r41 при retirement — 10 690 560 байт и
128 блоков. Публичные счётчики не разделяют время исполнения GPU и
служебную задержку внутри `waitIdle`.

**Журнал занял 20,1% окна r41.** Из 7,663 с на `fwrite` пришлось
0,001 с, на `fflush` — 2,607 с, на `fsync` — 5,054 с. Все три
операции вызывались 1 329 раз. Основная цена — принудительная отправка
и синхронизация каждой строки. У r41 стенное время выросло на 0,503 с,
I/O журнала — на 0,449 с, `waitIdle` в drain — на 0,079 с. Увеличение
времени журнала сопоставимо с большей частью разницы, но по одному
запуску каждой версии нельзя отделить вклад новой телеметрии от разброса
microSD и GPU.

Ожидание drain вложено в `batch_wait` и на пути draw в `draw_cpu`.
Время I/O измеряет блокировку потока CPU. Пока поток пишет журнал, GPU
может исполнять уже отправленные команды, поэтому выигрыш стенового
времени от сокращения I/O предстоит измерить отдельно.

## Единственная оптимизация для r42

**Пакетная durable-запись JSONL только на видимой карте.** Добавить
переключаемый режим с буфером до 64 КиБ. Вызывать `fflush` и `fsync`
один раз на пакет при заполнении или на первом безопасном checkpoint
после одной секунды. BOOT/Init остаются синхронными. При исключении,
контролируемой остановке и teardown накопленные строки записываются перед
финальной отметкой. Ошибка записи или sync сохраняет ошибочное состояние
и возвращает nonzero. Внезапное завершение может потерять хвост текущего
пакета.

Эта правка сокращает число вызовов `fflush`/`fsync` без изменения
лимитов батча, GPU-владения, команд, ресурсов и сохранений. Увеличение
лимита 64 оставлено вне r42, поскольку текущие данные показывают место
ожидания, но не объём работы, который исчезнет при укрупнении батча.
Сравнить два режима одной r42 на кадрах 60–240 при одинаковых условиях.
Критерии: меньше flush/sync и меньше стеновое время при тех же draw,
submissions, drains и совпадающих BGRA. При чтении журналов проверить
непрерывный seq, штатный `journal_close` и сохранение ошибки при сбое
вывода. Код r42 на этом этапе не менялся.
