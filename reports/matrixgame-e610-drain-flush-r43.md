# E610 r43. Отправка draw-батча через waitIdle

Аппаратная база — r42, режим `batch`, кадры 60–240. Время окна
31,051 с, 5,797 FPS. Из 3 240 отправок 3 060 сопровождались drain.
Все 3 060 вызваны лимитом 64 draw-пакета. `batch_wait` занял 14,133 с,
в том числе 13,981 с в `waitIdle`. Разница 0,152 с включает подготовку
и отправку списка, явный flush и сопутствующий код. Журнал занял
0,442 с. [Аппаратный отчёт r42](matrixgame-e610-journal-r42-hardware.md).

В SDK, связанном с r42 и r43, `waitIdle` ставит fence с включённым
сбросом GPU-кэша, вызывает `Queue::flush` и ждёт этот fence. Проверено
дизассемблированием обеих ELF. Самостоятельный flush перед `waitIdle`
может вызвать отдельную отправку работы до постановки fence. SDK также
сам отправляет команды при достижении внутренних лимитов.
[Документация deko3d](https://github.com/devkitPro/deko3d/blob/master/Primer.md#queues-dkqueue).

В r43 режим `--drain-flush=sdk` пропускает этот явный flush только у
drain по одному лимиту draw на видимой карте. `--drain-flush=explicit`
выбирает поведение r42. Оба запуска используют пакетный журнал и одну
NRO. Команды draw и барьеры приложения, очередность `submitCommands` →
`waitIdle` → проверка очереди → retirement, лимиты и структура
владения сохранены. При ошибке очереди владельцы остаются удержанными
до существующего пути teardown. Readback, writeback, Init, Present,
Reset и abort используют прежние операции.

`batch_explicit_flush_calls` показывает обращения приложения к flush
при drain. Если поток draw совпадёт с r42, между кадрами 60 и 240
показатель изменится с 3 060 в A до 0 в B. Счётчик не измеряет реальные
GPU kickoff. Ожидания сохраняются, а ускорение нужно замерить.
Критерии A/B — совпадение draw, отправок, drains, снимков и исправное
состояние очереди, затем сравнение стенового времени и двух профилей
ожидания. [Инструкция двух запусков](../docs/matrixgame-e610-drain-flush-r43-readme.ru.md).

**SOFTWARE PASS / HARDWARE PENDING.** Host ASan/UBSan, ARM64/QEMU
UBSan и Windows MSVC прошли целевые модели батчей, командной памяти
и upload. Модель replay сохранила порядок 208 808 draw, удержание
владельцев при ошибке submit/wait и хеш входов upload
`14588887670708592657`. Реальный путь deko3d проверен на уровне
исходников и devkitA64 link. Проверены SDK archive provenance,
отсутствие сильных undefined symbols и структура одной Interactive NRO.
Файлы прежних пакетов, ресурсы и сохранения сохранены.
